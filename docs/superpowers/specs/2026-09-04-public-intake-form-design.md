# Публичная форма приёма товара — дизайн

## Цель

Дать любому человеку (без входа в систему) заполнить простую веб-форму —
описание товара, свой табельный номер, категория, одно фото — и чтобы эти
данные копились в Supabase. Это первый шаг: результат пока не связывается с
существующими стеллажами/полками/коробами зоны «Без ШК» — только сбор
данных. Сама форма должна жить не на `mevukolov.github.io`, а на отдельном
адресе.

## Ключевое ограничение, определяющее архитектуру

Форма должна работать без авторизации — заполнить её может кто угодно, у
кого есть ссылка. Это осознанный выбор пользователя (простота важнее
контроля доступа на этом этапе), но он означает, что публичный API формы
нельзя дать право *читать* данные — иначе список заявок и все фото стали бы
видны всем в интернете. Поэтому: только `insert`, без `select`, для анонимного
ключа.

## Хостинг

Отдельная организация на GitHub — **wmsplus** (уже создана пользователем),
репозиторий `wmsplus.github.io` в этой организации → сайт будет на
`https://wmsplus.github.io/`. Тот же способ деплоя, что и у основного
приложения (GitHub Pages из main-ветки), просто в другом аккаунте — значит
и адрес другой, и от `mevukolov.github.io` это никак не зависит.

## Компоненты

### 1. `intake_submissions` (новая таблица в существующем проекте Supabase)

Тот же проект Supabase (`bgphllmzmlwurfnbagho`), что уже использует основное
приложение — отдельный проект не создаём, это просто ещё одна таблица в нём.

| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid, default `gen_random_uuid()` | |
| `created_at` | timestamptz, default `now()` | |
| `item_text` | text, not null | Название/описание товара |
| `employee_id` | integer, not null | Табельный номер сотрудника, заполняющего форму |
| `category` | text, not null, `check` из фиксированного списка | Одна из 13 категорий (см. ниже) |
| `photo_path` | text, not null | Путь к файлу в Storage-бакете `intake-photos` |

Фиксированный список категорий (одинаковый в `check`-constraint таблицы и в
`<select>` формы, чтобы значения не могли разойтись):
Одежда, Обувь, Косметика, Бытовая химия, Мебель, Электроника, Ювелирка,
Для авто, Для животных, Посуда, Еда, Посылка, КГТ.

RLS: включена, единственная политика — `insert` с `check (true)` для роли
`anon`. Никакой политики на `select`/`update`/`delete` для `anon` не
создаётся — значит прочитать список через публичный API снаружи нельзя,
только вы сами через панель Supabase (она использует `service_role`,
который RLS не ограничивает).

### 2. Storage bucket `intake-photos`

Публичный (`public: true`) — это значит, что файл открывается по прямой
ссылке, если её знать (например, из панели Supabase), но список файлов
бакета через API получить нельзя без `service_role`. Ограничения на уровне
бакета: `file_size_limit` (например 8 МБ) и `allowed_mime_types`
(`image/*`) — не дают анонимному клиенту загрузить произвольный файл любого
размера/типа, даже без какой-либо проверки на сервере.

Политика Storage: `insert` разрешён для `anon` в этот бакет, `list`/`update`/
`delete` — не разрешены.

### 3. Страница формы (`index.html` + `intake.js`, новый репозиторий)

Один статический файл, без сборки — тот же подход, что и во всём
остальном проекте (обычный `<script>`, никакого фреймворка). Поля:

- Описание товара — текстовое, обязательное.
- Табельный номер — числовое, обязательное.
- Категория — `<select>` с 13 вариантами, обязательное.
- Фото — `<input type="file" accept="image/*">`, ровно один файл,
  обязательное.
- Скрытое поле-ловушка (honeypot): невидимое обычному человеку CSS-ом
  (не `display:none`, а сдвиг за экран — так его не пропускают спам-боты,
  которые ищут `display:none`/`type=hidden`), но если оно всё же заполнено
  при отправке — форма молча не отправляется, без сообщения об ошибке
  (чтобы не подсказывать боту, что его поймали).

По кнопке «Отправить»:
1. Клиентская проверка обязательных полей и honeypot.
2. Загрузка фото в `intake-photos` (`supabase.storage.from(...).upload()`),
   имя файла — `${Date.now()}-${crypto.randomUUID()}.${расширение}`, чтобы
   исключить коллизии без какой-либо связи с личностью отправителя.
3. `insert` строки в `intake_submissions` с путём загруженного файла.
4. Экран успеха ("Заявка отправлена") с кнопкой "Отправить ещё одну" —
   без `alert()`, простым текстом на странице.

Визуально — тот же плоский, схематичный стиль без теней и градиентов, что
и в зоне «Без ШК» основного приложения (та же общая айдентика продукта,
хоть код и живёт в отдельном репозитории).

### 4. Просмотр заявок

Не входит в эту версию. Данные копятся в `intake_submissions` и
`intake-photos`, вы просматриваете их напрямую через панель Supabase
(Table Editor / Storage). Экран внутри `tasks.html` для просмотра списка —
следующий шаг, отдельная задача, когда станет понятно, что реально нужно
показывать сотрудникам склада.

## Явно не входит в первую версию

- Связь заявок с существующими стеллажами/коробами зоны «Без ШК» —
  заявка пока ни на что не влияет автоматически.
- Экран просмотра списка заявок внутри `tasks.html`.
- Капча или любая защита от целенаправленного (не случайного) спама —
  только honeypot-поле и ограничения на файл.
- Несколько фото на одну заявку — ровно одно.
- Редактирование или удаление уже отправленной заявки.
- Собственный домен вместо `wmsplus.github.io`.
