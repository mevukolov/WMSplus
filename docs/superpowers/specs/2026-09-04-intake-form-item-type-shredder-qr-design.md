# Форма приёма товара — тип товара, Шредер, сканирование QR — дизайн

## Цель

Добавить в уже работающий мастер (участок → тип товара → [категория] →
[наименование] → фото) ветвление по типу товара — «Мелкий товар»,
«КГТ», «Шредер» — с разными наборами шагов для каждого, и для «Шредер»
отдельно — сканирование QR-кода пустого стикера камерой телефона после
фото, значение которого пишется в базу как текст (само фото стикера не
сохраняется).

Фото становится обязательным на каждом пути (кнопка «Пропустить»,
добавленная в прошлой итерации, убирается полностью).

## Флоу экранов (заменяет текущий мастер `screenCategory → screenItemName → screenPhoto`)

```
Шаг 1 (новый, первый шаг мастера): выбор типа товара
  3 крупные кнопки: "Мелкий товар" / "КГТ" / "Шредер"

  Мелкий товар / КГТ ->
    Шаг 2: сетка из 12 категорий (та же, но без пункта "КГТ" -- он
           теперь отдельный тип на Шаге 1, не категория)

    Категория == "Посылка" ->
      Шаг 4: Фото (обязательно) -- Шаг 3 (наименование) пропускается
    Категория != "Посылка" ->
      Шаг 3: Наименование (Enter = дальше)
      Шаг 4: Фото (обязательно)

    После фото -> отправка -> "Заявка отправлена"

  Шредер ->
    Шаг 4: Фото (обязательно) -- Шаг 2 (категория) и Шаг 3
           (наименование) оба пропускаются
    Шаг 5 (только у Шредера): "Надёжно упакуйте товар, наклейте и
           отсканируйте пустой стикер" -- открывается камера,
           наведение на QR -- код распознаётся автоматически,
           сохраняется как текст (сама фото/кадр камеры не хранится)
    После сканирования -> отправка -> "Заявка отправлена"
```

Стрелка «назад» на каждом шаге ведёт туда, откуда реально пришли на
этот конкретный заход (не на фиксированный "предыдущий по списку"
экран):
- с Шага 2 (категория) -> Шаг 1 (тип товара)
- с Шага 3 (наименование) -> Шаг 2 (категория)
- с Шага 4 (фото) -> туда, откуда пришли именно в этот раз: Шаг 3
  (обычный путь), либо Шаг 2 (если пришли из "Посылка"), либо Шаг 1
  (если тип -- "Шредер")
- с Шага 5 (сканирование, только Шредер) -> Шаг 4 (фото)

«Заполнить ещё раз» после успеха -> всегда на Шаг 1 (выбор типа
товара) -- участок и личность по-прежнему не переспрашиваются, но тип
товара выбирается заново каждый раз (типы могут чередоваться от
заявки к заявке чаще, чем участок).

## Фото — теперь всегда обязательно

Кнопка «Пропустить» (добавленная в прошлой итерации) убирается
полностью из экрана фото. Сжатие и повторные попытки при сбое сети
(retry) остаются как есть — это не менялось.

## Сканирование QR (только у Шредера)

Через библиотеку `jsQR` (CDN, без сборки — такой же `<script>`-тег, как
у `supabase-js`): открывается камера (`getUserMedia`), видео рисуется
на скрытый `<canvas>` в реальном времени, `jsQR()` декодирует кадр за
кадром. Как только код найден — камера сразу останавливается
(освобождает ресурс), найденное значение сохраняется в JS-переменную и
происходит отправка. Пользователь не нажимает отдельную кнопку
«готово» — распознавание само завершает шаг.

Если камера недоступна (нет разрешения, нет камеры) — показать
понятную ошибку текстом на экране, не нативным `alert()`, с
возможностью повторить попытку.

## Изменения в данных (новая миграция)

`public.intake_submissions`:
- Новая колонка `item_type text not null check (item_type in ('Мелкий товар', 'КГТ', 'Шредер'))`.
- `category` теряет `not null` (у Шредера категории нет) — констрейнт
  на список значений сохраняется, но допускает `null`:
  `check (category is null or category in (...))`. Список значений —
  те же 12 (без «КГТ»).
- `item_text` теряет `not null` (пусто у Шредера и у «Посылки»).
- Новая колонка `sticker_code text` (nullable — только у Шредера).
- `photo_path` возвращает `not null` (фото снова всегда обязательно —
  откат nullable-изменения из прошлой итерации).

## Явно не входит в эту версию

- Проверка/валидация значения `sticker_code` против чего-либо (просто
  сохраняется как есть, что распознала камера).
- Возможность вручную ввести код стикера текстом, если камера совсем
  не работает — только сканирование.
- Ограничение количества попыток сканирования или таймаут — экран
  сканирования ждёт столько, сколько нужно.
