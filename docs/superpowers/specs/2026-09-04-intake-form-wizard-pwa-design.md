# Форма приёма товара — мастер, участки, PWA — дизайн

## Цель

Превратить текущую форму `wmsplus.github.io` (один экран: описание, ID,
категория, фото) в лёгкое веб-приложение, устанавливаемое на экран
домой телефона: один раз вводишь, кто ты и на каком участке, дальше —
быстрый пошаговый мастер на каждую заявку, без повторного ввода того,
что не меняется от заявки к заявке.

Это тот же репозиторий/сайт (`wmsplus/wmsplus.github.io`), просто новый
флоу поверх него. Ссылка остаётся одна на всех — установить её на свой
телефон может любой сотрудник, у которого она есть, без создания
отдельных аккаунтов или репозиториев.

## Ключевое отличие от текущей версии

Никакой настоящей авторизации не появляется — "вход" это просто
однократный ввод ID и ФИО, которые сохраняются в `localStorage`
телефона и подставляются во все последующие заявки автоматически. Это
явно НЕ security-механизм (как и раньше, никакой проверки личности
нет) — только избавление от повторного набора одного и того же на
телефоне.

## Локальное состояние устройства (localStorage)

Три ключа, ничего не идёт в Supabase, пока не отправлена сама заявка:

| Ключ | Значение |
|---|---|
| `wmsplus_intake_employee_id` | число |
| `wmsplus_intake_full_name` | строка |
| `wmsplus_intake_area` | `'ХАБ'` \| `'Упаковка'` \| `'Маркетплейс'` |

## Флоу экранов

```
Нет employee_id/full_name?
  → Экран "Введите ваш ID" (число, Enter = дальше)
  → Экран "Введите ваше ФИО" (текст, Enter = дальше)
  → сохранить в localStorage

Нет area?
  → Экран выбора участка: 3 крупные кнопки (ХАБ / Упаковка / Маркетплейс)
  → сохранить в localStorage
  → (внизу этого экрана: кнопка "Сменить пользователя" -- очищает
     employee_id/full_name/area и возвращает к вводу ID)

Есть employee_id, full_name и area?
  → сразу в мастер заполнения (шаг 1)
```

На всех экранах мастера (не на экранах входа/выбора участка) — плашка
слева сверху с названием текущего участка и карандашиком; тап по ней
переходит на экран выбора участка (не стирает identity, только area).

### Мастер заполнения одной заявки

```
Шаг 1: сетка из 13 квадратных кнопок-эмодзи (категории), больше
       ничего на экране. Тап -> Шаг 2.

Шаг 2: сверху -- "Категория: [эмодзи] [название]"
       поле "Наименование" (текст, Enter = дальше)
       стрелка назад -> Шаг 1 (категория сбрасывается)

Шаг 3: кнопка "Фото" (открывает выбор файла) + кнопка "Пропустить"
       стрелка назад -> Шаг 2 (наименование остаётся как было)

       Кнопка "Фото" -> сжатие (уже есть) -> отправка:
       employee_id + full_name + area + item_text + category +
       photo_path (или null, если пропущено)

       Кнопка "Пропустить" -> та же отправка сразу, без фото
       (photo_path = null)

После успеха: экран "Заявка отправлена", кнопка "Заполнить ещё раз"
       -> сразу Шаг 1 мастера (участок и личность НЕ переспрашиваются).
```

Отправка (сеть) происходит только на шаге 3 — шаги 1-2 только копят
значения в JS-переменных, ничего не уходит в Supabase раньше времени.
Загрузка фото и вставка строки используют уже существующий retry
(3 попытки) из текущей версии — просто становится не обязательным
шагом, а не последним звеном единственного пути.

## PWA / установка на экран домой

- `manifest.json`: имя приложения, `display: standalone` (открывается
  без адресной строки браузера, как отдельное приложение),
  `theme_color`/`background_color` из палитры сайта (`#623CEA` /
  `#DED4FF`), иконка.
- Иконка — сгенерированная (не файл от пользователя): фиолетовый
  квадрат (`#623CEA`) с белым символом коробки, в нескольких
  стандартных размерах (192×192, 512×512) + `apple-touch-icon` для
  iOS (у iOS свой, отдельный от `manifest.json` способ подключения
  иконки для "На экран «Домой»").
- `<meta name="viewport">` с `viewport-fit=cover` и
  `user-scalable=no`; на мобильных ширинах (`max-width: 768px`)
  `html, body { overflow: hidden; height: 100%; }` — полностью убирает
  скролл, все экраны мастера должны укладываться в `100dvh`.

## Изменения в данных (новая миграция)

`public.intake_submissions`:
- Добавить `full_name text not null` (ФИО).
- Добавить `area text not null check (area in ('ХАБ', 'Упаковка', 'Маркетплейс'))`.
- `photo_path` теряет `not null` (фото теперь можно пропустить) —
  `alter table ... alter column photo_path drop not null`.

Все остальные ограничения (длина `item_text`, `employee_id > 0`,
insert-only для `anon`, список категорий) остаются как есть.

## Явно не входит в эту версию

- Проверка ID/ФИО против существующего реестра сотрудников основного
  приложения (WMS+) — вводится как есть, без сверки.
- Возможность повторно загрузить/заменить фото после пропуска (заявка
  уже отправлена без фото — донести фото можно только новой заявкой).
- Синхронизация identity/участка между устройствами одного сотрудника
  — состояние живёт только в `localStorage` конкретного телефона.
- Свой (не сгенерированный) логотип приложения.
