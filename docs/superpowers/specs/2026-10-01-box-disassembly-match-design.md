# Короб "Без ШК": сплит-панель опознания при разборе — дизайн

**Спек:** объединяет разбор короба (`no_shk_zone.js`), старый поиск по чистым списаниям
(`renderNoShkReviewModal` в `tasks.js` — сейчас нигде не подключён) и систему
сопоставления с задачами, построенную ранее в этой же сессии
(`wms_no_shk_bulk_match_and_persist`, `openNoShkMatchModal`/`confirmNoShkMatch`).

## Цель

При разборе короба клик по товару сейчас открывает только фото + кнопку
"Присвоить ШК" (`openPhotoLightbox` в `intake_search.js`). Нужно добавить справа
поиск/автоподбор совпадений — по открытым задачам и по "чистым списаниям"
(`pure_losses_rep`) — чтобы опознать товар электронно там, где это возможно, и
прибегать к физическому стикеру только когда ничего не нашлось.

## Архитектура: что переиспользуем, что новое

| Кусок | Статус | Источник |
|---|---|---|
| Левая панель (фото + мета + "Присвоить ШК") | переиспользуем как есть | `openPhotoLightbox`/`renderAssignRow`/`confirmAssignSticker`, `intake_search.js` |
| Поиск по `pure_losses_rep` (механика ввода, visual-variant фуззи, сортировка) | переиспользуем функции напрямую (та же IIFE-область в `tasks.js`) | `fetchNoShkPureRows`, `buildNoShkVisualVariants`, `sortNoShkPureRows`, `renderNoShkRowsHtml`-паттерн, `markNoShkPureAsFound` |
| Точное/нечёткое сопоставление с задачами (бренд+название) | переиспользуем логику, но как **новый живой RPC на один товар**, не батч-крон | та же пара порогов 0.5/0.35 и `wms_task_nm_index`+`wms_nm_directory`, что в `wms_no_shk_bulk_match_and_persist` |
| Вердикт по задаче ("Опознать") | переиспользуем ядро, выношу в общую функцию | текущее тело `confirmNoShkMatch` (claim, разделение тары, история, вердикт по стикеру) без привязки к `no_shk_matches`-бухгалтерии очереди |
| Завершение короба / зона | новое | — |

`renderNoShkReviewModal` сейчас **мёртвый код** (функция есть, вызвать её неоткуда) —
его поисковые функции просто вызываются из нового места, сам модальный шелл
(`#noShkReviewModal`) не трогаем/не используем.

## Компоненты

### 1. Сплит-модалка (замена `openPhotoLightbox` при вызове из разбора короба)

Два столбца внутри одной модалки:
- **Левый** — текущий `openPhotoLightbox`-контент как есть (фото/мета/"Присвоить ШК").
- **Правый** — новая панель поиска/автоподбора.

Открывается из `no_shk_zone.js`'s клика по тайлу (`disassembleTileHtml` → сейчас
`window.__openIntakeSubmissionCard(item)`) — передаём флаг "режим разбора короба",
чтобы вне разбора короба (поиск "Лента без ШК", история задачи) лightbox оставался
как сейчас, без правой панели.

### 2. Правая панель: поиск

Один текстовый инпут сверху, **та же немгновенная механика ввода**, что у
`renderNoShkReviewModal` — поиск по кнопке/Enter, не на каждый символ
(дословно: "чтобы страница не превращалась в кипящий чайник" — сохраняю этот
принцип).

- **Пусто (по умолчанию при открытии)** — автоподбор по собственным данным товара:
  - Задачи: новый RPC `wms_no_shk_item_task_matches(p_submission_id, p_query := null)` —
    через `wb_nm_candidates` товара ищет задачи точным nm и нечётким
    бренд+название (как в батч-функции), **без оконного ограничения по дате**
    (это разовый ручной клик оператора с товаром в руках, не автоматическая
    очередь — ложные совпадения дёшево отклонить глазами, в отличие от очереди
    на автозакрытие).
  - Списания: `fetchNoShkPureRows`, засеянный собственным nm/брендом/названием
    товара (из `wms_nm_directory` по тем же `wb_nm_candidates`), а не текстом
    инпута.
- **Введён текст** — обе секции ищут по тексту: задачи через тот же RPC с
  `p_query`, списания — обычный вызов `fetchNoShkPureRows(query)` как сегодня.

Результат — два отдельных списка-секции ("Задачи" / "Списания"), карточка как у
`noShkMatchCardHtml`/`renderNoShkRowsHtml` (фото, название, бренд, ШК/НМ), с
кнопкой **"Опознать"**, которая показывается по наведению (hover), не всегда
видна — так просил пользователь.

### 3. Опознание — два пути

**По задаче:** выношу общее ядро `confirmNoShkMatch` (клейм через
`wms_intake_mark_matched`, разделение тары при необходимости, запись истории
`task_no_shk_found`, применение вердикта `applyNoShkStickerVerdict`, если на
товаре уже был стикер стола старшего) в отдельную функцию `resolveNoShkTaskMatch(row,
matchedItem, submission)`, которую вызывают и старый `confirmNoShkMatch`
(очередь), и новая панель (без записи в `no_shk_matches` — она просто сразу
опознаёт и закрывает).

**По списанию:** переиспользую `markNoShkPureAsFound(row)` как есть (пишет
`decision="Найден"` в `pure_losses_rep`), и **дополнительно** помечаю
`intake_submissions` как опознанный по списанию (новое поле, см. ниже) — чтобы
"Лента без ШК" и разбор короба видели это состояние.

### 4. "Решено" без физического стикера

Сейчас завершённость товара в коробе = `Boolean(item.sticker_code)`
(`disassembleTileHtml`, `refreshDisassembleItems`). Расширяю до:
`sticker_code OR matched_task_id OR matched_pure_loss_id` — опознание по
задаче/списанию закрывает товар без требования реального стикера; стикер
нужен только когда в панели ничего не нашлось и оператор жмёт "Присвоить ШК".

**Миграция:** `intake_submissions` — добавить `matched_pure_loss_id text` (id
строки `pure_losses_rep`, текстом, т.к. имя PK-колонки в `pure_losses_rep`
определяется динамически тем же способом, что и в `buildNoShkPureUpdateFilters`).
`matched_shk`/`matched_at`/`matched_by_id`/`matched_by_name` переиспользую для
обоих путей (и задача, и списание пишут в эти же поля, конкретный путь виден
по тому, какое из `matched_task_id`/`matched_pure_loss_id` заполнено).

`wms_no_shk_box_contents` RPC — добавить `matched_task_id`,
`matched_pure_loss_id` в возвращаемые поля (как уже есть `matched_shk`,
`sticker_code` у other вызовов этого флоу — тут их не было, добавляю).

### 5. Состояние тайла в коробе

Решённый товар (любым из трёх путей) — тайл уезжает в конец грида
(`disassembleItems`, пересортировка перед рендером: нерешённые сначала, решённые
в конце в порядке решения), фон зелёный (`.no-shk-disassemble-tile.is-done` —
уже есть частично, усиливаю цветом), фото притушено (`filter: brightness(.7)`
или `opacity`, на усмотрение при реализации).

### 6. Завершение короба → зона "Разобранные короба"

`completeDisassembleBox` сейчас пишет только `disassembled_at`/`disassembled_by`.
Добавляю: `shelf_id = null` (физически освобождает полку — сейчас этого не
происходит вообще, подтверждено при разведке: короб висит на полке вечно).
Основной грид стеллажей (`loadZone`) начинает **фильтровать**
`disassembled_at is null`, чтобы разобранные короба не засоряли полки
визуально и в счётчике `X / capacity`.

Новая секция в `#noShkZoneModal` — "Разобранные короба": список боксов
`disassembled_at is not null`, отсортированный по `disassembled_at desc`.
Видна только внутри "Зона Без ШК" (не на главном экране задач).

### 7. Историческое наполнение

Клик по разобранному коробу в новой секции → тот же `openDisassembleFullscreen`/
`renderDisassembleGrid`, но в режиме read-only (без клика по тайлам, открывающего
опознание — можно открыть карточку только на просмотр фото/результата, без
кнопок). Данные те же (`wms_no_shk_box_contents`), просто без интерактивных
действий.

## Вне рамок этой спеки

- Точный UI "Чистые списания" как отдельная вкладка в "Разборе" (из более
  раннего, другого запроса) — не трогаем, здесь списания используются только
  как источник данных для поиска.
- Миграция существующих уже-разобранных коробов (задним числом освободить им
  полки) — один разовый `update`, сделаю при реализации, не меняет дизайн.
