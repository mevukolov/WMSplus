# Форма приёма — тип заявки (Без ШК/2 ШК/Пустая упаковка), категории, анимации, смена — дизайн

## Цель

Перед уже существующим мастером «Без ШК» (тип товара → категория →
наименование → фото) добавить ещё более верхний уровень выбора — что
вообще за заявка: сам товар без штрихкода (существующий флоу), два
штрихкода на одном товаре, или пустая упаковка. Плюс сузить списки
категорий под тип товара, добавить лёгкие анимации переходов между
экранами и постоянно видимую шапку с датой/сменой.

## Найдено при подготовке: таблица `2shk_rep`

Ветки «2 ШК на товаре» и «Пустая упаковка» — НЕ про наш собственный
`intake_submissions`. Это уже существующая таблица `public.2shk_rep`
(без RLS, `anon` имеет полный доступ), в которую сейчас пишет отдельный
процесс на базе Яндекс.Форм. Наши новые ветки формы должны писать в ту
же таблицу, в её же формате, а не заводить что-то своё:

| Колонка | Тип | Как заполняем |
|---|---|---|
| `shk1` | text | «Верный ШК» (ветка «2 ШК») или единственный ШК (ветка «Пустая упаковка») |
| `shk2` | text | «Неверный ШК» (ветка «2 ШК»); `' '` — буквально один пробел — для «Пустая упаковка» (так уже оформлены тысячи существующих строк, сохраняем формат) |
| `eventtype` | text | `'Два ШК'` или `'Пустая упаковка'` — точные строки, уже используются в данных |
| `media` | text | Полная публичная ссылка на фото в Supabase Storage (существующие строки хранят полные URL на файлы Яндекс.Форм — сохраняем тот же формат: не путь, а рабочая ссылка) |
| `wh_id` | text | Фиксированно `'50144199'` (по решению пользователя — единственное реальное значение склада, соответствия «участок → wh_id» нет) |
| `created_at` | timestamptz | По умолчанию (`now()`), не задаём вручную |

Идентичность (ID/ФИО) и участок, которые пользователь уже ввёл на
предыдущих экранах, в эту таблицу не пишутся — в её схеме для них нет
места, и это осознанно (данные всё равно остаются в `localStorage`
устройства для следующих заявок).

## Флоу экранов

```
Экран "Тип заявки" (новый, первый экран мастера после выбора участка):
  3 крупные кнопки: "Товар без ШК" / "2 ШК на товаре" / "Пустая упаковка"

  "Товар без ШК" -> существующий флоу без изменений в структуре
                     (Мелкий товар / КГТ / Шредер -> ... -> фото),
                     кроме сужения списка категорий (см. ниже)

  "2 ШК на товаре" -> форма из 3 обязательных полей:
                     "Введите верный ШК" (только цифры)
                     "Введите неверный ШК" (только цифры)
                     "Добавьте фото"
                     -> запись в 2shk_rep (eventtype='Два ШК')

  "Пустая упаковка" -> форма из 2 обязательных полей:
                     "Введите ШК" (только цифры)
                     "Добавьте фото"
                     -> запись в 2shk_rep (eventtype='Пустая упаковка')
```

«Заполнить ещё раз» после успеха любой из трёх веток -> всегда на
экран «Тип заявки» (не переспрашивая участок/личность).

Оба новых экрана (2 ШК, Пустая упаковка) используют уже существующие
сжатие фото и повторные попытки при сбое сети — та же логика, что и в
основном флоу, просто с другим адресатом вставки (`2shk_rep` вместо
`intake_submissions`) и без выбора категории/наименования вовсе.

Поля ШК — только цифры: `inputmode="numeric"`, и проверка на клиенте
(`/^\d+$/`) перед отправкой, с понятной ошибкой текстом при нарушении.

## Сужение категорий для «Товар без ШК»

- Мелкий товар: без «Мебель» (11 категорий вместо 12).
- КГТ: без «Одежда», «Косметика», «Ювелирка» (9 категорий вместо 12).
- Список категорий, доступных при каждом типе, — константа в коде, не
  вычисляется динамически из полного списка минус что-то — так надёжнее
  и нагляднее при следующих правках.

## Анимации переходов

Лёгкий fade + небольшой вертикальный сдвиг (~150–200 мс) при смене
активного экрана. Никаких тяжёлых эффектов (blur, парение частиц и
т.п.) — телефоны, на которых открывается сайт, разного класса, а сама
задача сотрудника — быстро провести заявку, а не любоваться анимацией.

## Шапка со сменой

Постоянно видимый элемент (дата + подпись смены), не мешающий уже
существующим плашке участка и стрелке назад.

Логика:
- 08:00–19:59 — «Дневная смена», одна дата (сегодня).
- 20:00–23:59 — «Ночная смена», диапазон сегодня–завтра.
- 00:00–07:59 — «Ночная смена», диапазон вчера–сегодня.

Формат дат — `ДД.ММ`, диапазон через дефис (`06.08-07.08`).

## Явно не входит в эту версию

- Проверка/маска цифр ШК на конкретную длину (штрихкоды бывают разной
  длины) — только «состоит из цифр», без ограничения по количеству.
- Соответствие участка (ХАБ/Упаковка/Маркетплейс) и `wh_id` — пока
  фиксированное значение для всех.
- Просмотр/админка заявок из `2shk_rep` внутри этой формы — данные
  туда уходят, читает их существующий процесс/админка вне этой формы.
